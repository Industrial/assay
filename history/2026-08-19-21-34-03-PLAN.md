# Assay: Roadmap to Becoming the Best Nix Testing Framework

## Vision
To be the undisputed best choice for unit testing in the Nix ecosystem, excelling in performance, features, ergonomics, and ecosystem integration.

## Current Strengths (from comparison.md)
- Rich claim algebra
- Process isolation
- Structural diffs
- Multi-suite repo throughput
- CI formats (human, JSON, TAP)
- Colocated discovery
- Timeouts/flaky retry
- Migration path from runTests

## Current Weaknesses and Trade-offs
|1. Raw eq microbenchmark: ~1.8x slower than nix-unit for trivial equality-only suites.
|2. Not yet packaged in nixpkgs (ecosystem default).
|3. Migration from nix-unit requires manual conversion (though we have a path for runTests).
|4. Historical telemetry latency (already fixed in current version).
|
## Current Benchmark Baseline

| Benchmark | Assay (batch) | Assay (no-batch) | nix-unit |
|-----------|---------------|------------------|----------|
| 50× `eq 1+1=2` (median of 5) | **45.2 ms** | 94 ms | **24.7 ms** |
| Full repo **233** claims | **~464 ms** median | — | n/a (no colocated discovery) |

*Any change must improve these numbers (lower time) or improve functionality without worsening these baseline numbers.*
*When an improvement is made, the baseline should be updated to reflect the new performance.*

## Phase 1: Performance Micro-optimizations (Target: Close the microbenchmark gap)
- [ ] Implement an optional in-process eval backend for safe, cheap claims (eq of JSON primitives).
- [ ] Optimize the batching mechanism to reduce overhead further (e.g., persistent nix eval process pool).
- [ ] Benchmark and tune the current batching to maximize the number of claims per batch.
- [ ] Consider compiling simple Nix expressions to Rust functions (via a JIT or AOT) for the fastest path.

## Phase 2: Ecosystem and Packaging (Target: Get Assay into nixpkgs and widely adopted)
- [ ] Write a nixpkgs package for Assay and submit a PR.
- [ ] Update the flake.nix to provide a flake app and library that are nixpkgs-compatible.
- [ ] Create a tutorial and documentation for using Assay in nixpkgs.stdenv.mkDerivation.
- [ ] Work with the nixpkgs community to adopt Assay as the recommended testing framework.

## Phase 3: Migration Tooling (Target: Zero-cost migration from nix-unit and runTests)
- [ ] Develop `assay convert nix-unit` to convert nix-unit test files to Assay suites.
- [ ] Develop `assay convert runTests` to convert runTests expressions to Assay suites.
- [ ] Provide a compatibility mode that allows running existing nix-unit tests without conversion (by implementing a nix-unit runner in Assay).

## Phase 4: Benchmarking and Proof (Target: Continuously prove superiority)
- [ ] Expand the benchmark suite to include:
    * Single test latency (cold and warm)
    * Memory usage per test
    * Throughput for mixed claim types
    * Scalability with number of tests
- [ ] Automate benchmark runs in CI and publish results to a dashboard.
- [ ] Create a `assay benchmark` subcommand for easy local benchmarking.
- [ ] Regularly compare against nix-unit, runTests, namaka, and nixt.

## Phase 5: Extend Claim Algebra and Features (Target: Most expressive and useful claim set)
- [ ] Add new claim types:
    * `assay.moduleEval` for testing NixOS module options (beyond just `assay.module`).
    * `assay.drvBuild` for testing that a derivation builds successfully.
    * `assay.drvOutput` for testing specific outputs of a derivation.
    * `assay.property` for property-based testing (using a crate like proptest or quickcheck).
- [ ] Improve existing claims:
    * Make `assay.throws` support checking multiple error messages or types.
    * Enhance `assay.snapshot` with automatic updating and better diff output.
- [ ] Add support for test fixtures and setup/teardown (without breaking isolation).

## Phase 6: Replace Nix Built-ins with Rust Equivalents (Where Beneficial)
- [ ] Identify Nix built-ins that are bottlenecks in test suites (e.g., string manipulation, attrset operations).
- [ ] Implement efficient Rust equivalents in existing crates (nixq, nixdrv, etc.) or new crates.
- [ ] Expose these Rust functions to the Assay DSL via a new claim type or as helper functions in the Nix context.

## Success Metrics
- Assay's weighted score in the decision matrix (from docs/comparison.md) increases to 4.8+.
- Assay is packaged in nixpkgs and used by default in new nixpkgs contributions.
- Benchmarks show Assay is faster than nix-unit for mixed workloads and only slightly slower for trivial eq (with the goal of parity or better via optimizations).
- The `assay convert` tools are widely adopted and reduce migration effort to minutes.
- **Benchmark numbers (50× eq and full repo claims) must not regress; improvements should lower the time or improve functionality without worsening these baseline numbers.**
